# Оценка узких мест при миграции и рекомендации

## Выявленные проблемы по категориям

### Инфраструктура

| Проблема                                          | Влияние                                                                                                                |
|---------------------------------------------------|------------------------------------------------------------------------------------------------------------------------|
| Единый физический сервер - SPOF                   | При отказе - остановка бизнеса                                                                                         |
| Нет Kubernetes-кластера и облачной инфраструктуры | Длительная подготовка перед началом миграции: namespace isolation, network policies, Istio service mesh                |
| Нет сегментации сети - всё в одном VLAN           | Невозможно изолировать старую и новую системы; ККМ, рабочие станции и серверы в одном сегменте                         |
| Недостаток HA/DR, логов и трассировки             | Нет резервного копирования, нет мониторинга, при сбое невозможно диагностировать причину; потеря данных невосстановима |

### Приложения

| Проблема                                                 | Влияние                                                                                                                                       |
|----------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| Скрытая бизнес-логика в Excel и ручных действиях         | Формулы, макросы и ручные процедуры не задокументированы; при миграции логика может быть утеряна или воспроизведена некорректно               |
| Риск распределённого монолита при поспешной декомпозиции | Неправильные границы микросервисов приведут к сильной связанности, сетевым задержкам и сложности отладки; переделка обойдётся дороже монолита |
| 1С файловый режим                                        | Нет API, плохая масштабируемость                                                                                                              |
| Нет CI/CD и автоматизированного тестирования             | Высокий риск регрессий при развёртывании новых компонентов; ручные релизы - долго и ненадёжно                                                 |
| Порталы пациента и сотрудника - разработка с нуля        | Два полноценных веб/мобильных приложения с интеграцией RBAC/ABAC и consent management UI; значительный объём разработки                       |

### Безопасность

| Проблема                                        | Влияние                                                                                        |
|-------------------------------------------------|------------------------------------------------------------------------------------------------|
| Нет RBAC/ABAC - все сотрудники видят все данные | Кассир видит медкарты, складской работник - платежи; нарушение принципа минимальных привилегий |
| Нет аудита, алертинга и контроля доступа        | Невозможно обнаружить утечку, расследовать инцидент                                            |
| Нет шифрования At Rest - данные открыты         | При физическом доступе к серверу все ПДн и мед. данные доступны                                |
| Передача данных без шифрования (OLE, TCP)       | Данные перехватываются в сети; OLE/TCP не поддерживают TLS; все интеграции уязвимы             |
| Отсутствует процесс согласия ПДн                | Нет правового основания для обработки ПДн; при проверке регулятором - штрафы и предписания     |
| Нет контроля утечек (DLP)                       | ПДн могут быть скопированы на USB, отправлены по почте или напечатаны без контроля             |
| Нет механизма удаления данных по запросу        | Невозможно реализовать право на забвение; данные разбросаны по Excel, 1С, файлам               |

### Данные

| Проблема                                        | Влияние                                                                                         |
|-------------------------------------------------|-------------------------------------------------------------------------------------------------|
| Неструктурированные Excel                       | Нет схемы, дубли, длительный ETL-процесс с ручной валидацией                                    |
| Двойной учёт (Excel + 1С)                       | Рассинхронизация, необходимо определить источник правды для каждого типа данных перед миграцией |
| ПДн в именах папок (ФИО + дата рождения)        | Замена на UUID при миграции; сохранение трассируемости; обновление всех ссылок в файлах и базах |
| Большой объём JPG/PDF сканов документов         | Длительное время миграции в S3-совместимое хранилище                                            |
| Миграция в 4 PostgreSQL (CRM, Мед, Лаб, Записи) | Проектирование схемы каждой БД, маппинг Excel-столбцов                                          |

### Интеграции

| Проблема                                       | Влияние                                                                                                                       |
|------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------|
| OLE/TCP - point-to-point усложняет переход     | Устаревшие протоколы не совместимы с микросервисной архитектурой; замена на REST/gRPC + mTLS требует переписывания интеграций |
| Лаборатория - ручная загрузка данных           | Нет интеграционного контракта                                                                                                 |
| ККМ через TCP/IP + OLE -                       | Незащищенные соедниения, нет REST API                                                                                         |
| Coexistence old/new: гонки и рассинхрон данных | В период параллельной работы старой и новой системы - риск потери данных, дублирования записей и конфликтов при обновлении    |

### Процессы и персонал

| Проблема                                                       | Влияние                                                                                                    |
|----------------------------------------------------------------|------------------------------------------------------------------------------------------------------------|
| IT-команда мала (3 чел.) для миграции 18 систем                | Недостаточно ресурсов для параллельной поддержки двух систем и развёртывания 18 компонентов                |
| Нет опыта микросервисов, K8s, CDC                              | Ошибки проектирования, замедление разработки, риск распределённого монолита                                |
| Нет DevOps и плана отката (rollback)                           | Ручное развёртывание; при критическом сбое - потеря данных и остановка бизнеса; нет возможности откатиться |
| Бизнес-процессы не задокументированы; бизнес нельзя остановить | Риск потери бизнес-логики при переносе                                                                     |
| Отсутствие DevSecOps                                           | Нет проверок безопасности в CI/CD; уязвимости попадают в продакшн                                          |
| Отсутствие SRE и Data-инженеров                                | CDC-пайплайны требуют специализированных навыков, которых нет в команде                                    | 
| Обучение 3 ролей (ресепшен, врач, админ)                       | 3 отдельных программы обучения новым порталам и процессам; простой и временное снижение производительности |
| Change management: согласия пациентов, DLP-правила             | Пациенты должны быть информированы о новых согласиях; сотрудники - о правилах DLP и классификации данных   |
