# Задание 1. Анализ безопасности системы

## 1. Выявленные конфиденциальные данные

### Персональные данные пациентов (PII / ПДн)
- ФИО, дата рождения, телефон, электронная почта
- Адрес прописки, место работы/учёбы
- Информация о хронических заболеваниях
- Результаты анализов и заключения специалистов
- Медицинские карты (содержат врачебную тайну - ст. 13 ФЗ-323)
- Договоры с пациентами (содержат паспортные данные, подписи)

### Данные сотрудников
- Кадровые данные (ФИО, паспорт, ИНН, СНИЛС, адреса)
- Данные по зарплате и налоговые документы
- Учётные записи Active Directory (логины, пароли)

### Финансовые данные
- Платёжная информация пациентов (данные чеков ККМ)
- Бухгалтерская отчётность
- Данные P&L, ABC-анализа

### Данные лаборатории
- Реестры анализов за день (привязка пациент - результат)
- Результаты исследований в привязке к ФИО пациента

## 2. Аудит мер безопасности - проблемные зоны

### 1. Отсутствие классификации данных
Описание: Данные не классифицированы по уровням конфиденциальности. Нет разделения на общедоступные, внутренние, конфиденциальные и данные, составляющие врачебную тайну.

Нарушение: Невозможно применять дифференцированные меры защиты. Нарушение принципа Data Minimization.

Риск: Высокий. Все сотрудники имеют одинаковый доступ к данным любой чувствительности.

### 2. Хранение ПДн в незашифрованных Excel-файлах на общем диске
Описание: Журналы приёма, списки пациентов, медицинские карты, реестры анализов хранятся в Excel-файлах на файловом сервере без шифрования.

Нарушение: Нарушение требований ФЗ-152 - необходимость обеспечения конфиденциальности ПДн.

Риск: Критический. Любой сотрудник с доступом к сетевому диску может скопировать данные всех пациентов.

### 3. Отсутствие контроля доступа к файлам с конфиденциальными данными
Описание: Доступ к данным ограничен только доменной аутентификацией (Active Directory). Нет ролевой модели (RBAC/ABAC), нет гранулярного управления правами.

Нарушение: Нарушение принципов Privacy by Design (минимизация доступа). Нарушение принципа наименьших привилегий.

Риск: Критический. Кассир может видеть медицинские карты, сотрудник склада - платёжные данные.

### 4. Отсутствие аудита доступа к данным
Описание: Нет журналирования действий пользователей при работе с файлами: кто открыл, изменил, скопировал или удалил файл - не фиксируется.

Нарушение: Невозможность расследования инцидентов. Нарушение требований ФЗ-152 (контроль обработки ПДн).

Риск: Высокий. Невозможно обнаружить утечку или несанкционированный доступ.

### 5. Передача данных между системами без шифрования
Описание: Данные между 1С:Бухгалтерия, 1С:Торговля, ККМ и файловым сервером передаются по внутренней сети без шифрования (OLE, TCP/IP).

Нарушение: Нарушение принципа Data Encryption in Transit. Уязвимость к перехвату трафика (man-in-the-middle).

Риск: Средний (локальная сеть), но критический при расширении на филиалы.

### 6. Именование папок пациентов содержит ПДн
Описание: Папки пациентов именуются по схеме «Pacient1-FIO-BD» (ФИО и дата рождения в имени папки). Это значит, что персональные данные видны в структуре каталогов.

Нарушение: Нарушение принципов Data Minimization и Privacy by Design - ПДн должны быть скрыты/обезличены.

Риск: Высокий. Просмотр файловой структуры раскрывает список пациентов.

### 7. Нет механизма удаления/обезличивания данных по запросу
Описание: Отсутствует процедура реагирования на запрос субъекта ПДн об удалении данных.

Нарушение: Прямое нарушение ФЗ-152.

Риск: Высокий. Финансовые и репутационные последствия при обращении субъекта или проверке регулятора.

### 8. Отсутствие шифрования данных при хранении (Data at Rest)
Описание: Файлы на сервере, базы 1С хранятся без шифрования. Нет BitLocker, нет шифрования на уровне БД.

Нарушение: Нарушение защиты данных.

Риск: Критический. При физическом доступе к серверу все данные доступны.

### 9. Единая точка отказа - физический сервер в офисе
Описание: Все сервисы (AD, DNS, DHCP, Exchange, файловый сервер) развёрнуты на одном физическом сервере в офисе. Нет резервного копирования в удалённое хранилище.

Нарушение: Нарушение принципа доступности. Нет плана аварийного восстановления.

Риск: Критический. Пожар, потоп или кража сервера = потеря всех данных.

### 10. Двойной учёт платежей (Excel + 1С)
Описание: Кассиры ведут двойной учёт - в Excel и 1С. Это создаёт рассинхронизацию и увеличивает площадь атаки.

Нарушение: Нарушение целостности данных. Увеличение поверхности атаки за счёт дублирования.

Риск: Средний. Несогласованность данных, дополнительные точки утечки.

### 11. Отсутствие сегментации сети
Описание: Все сотрудники, ККМ и серверные сервисы находятся в одном сетевом сегменте.

Нарушение: Нарушение принципа сегментации и изоляции.

Риск: Высокий. Компрометация одного рабочего места даёт доступ ко всей инфраструктуре.

### 12. Отсутствие политики обработки согласий на обработку ПДн
Описание: Не описан процесс получения, хранения и отзыва согласий пациентов на обработку персональных данных.

Нарушение: Нарушение ФЗ-152 - обработка ПДн без согласия субъекта.

Риск: Высокий. Штрафы Роскомнадзора, судебные иски.

### 13. Почтовый сервер без DLP и контроля утечек
Описание: Exchange Mail Server используется для внутренней переписки, но нет систем предотвращения утечек данных (DLP).

Нарушение: Конфиденциальные данные могут быть отправлены по email без контроля.

Риск: Средний. Случайная или намеренная отправка ПДн пациентов по почте.

## 3. Рекомендации по улучшению

### Список данных для защиты и способы защиты

| Тип данных                   | Категория                                   | Способ защиты                                            |
|------------------------------|---------------------------------------------|----------------------------------------------------------|
| ФИО пациента                 | ПДн                                         | Шифрование (AES-256), обезличивание при аналитике        |
| Дата рождения                | ПДн                                         | Шифрование, обезличивание (замена на возрастную группу)  |
| Телефон, email               | ПДн                                         | Шифрование, маскирование (показ последних 4 символов)    |
| Адрес прописки               | ПДн                                         | Шифрование, обезличивание                                |
| Место работы/учёбы           | ПДн                                         | Шифрование, обфускация                                   |
| Хронические заболевания      | Специальная категория ПДн + врачебная тайна | Шифрование (AES-256), строгий RBAC (только лечащий врач) |
| Медицинские карты            | Специальная категория ПДн + врачебная тайна | Шифрование, RBAC, аудит доступа                          |
| Результаты анализов          | Специальная категория ПДн + врачебная тайна | Шифрование, обезличивание при передаче, RBAC             |
| Договоры пациентов           | ПДн + коммерческая тайна                    | Шифрование, ограниченный доступ                          |
| Платёжные данные             | Финансовые данные                           | Шифрование, маскирование номера карты (PCI DSS)          |
| Кадровые данные сотрудников  | ПДн сотрудников                             | Шифрование, RBAC (только HR и бухгалтерия)               |
| Зарплатные ведомости         | Финансовые + ПДн                            | Шифрование, строгий RBAC                                 |
| Данные ККМ                   | Финансовые                                  | Шифрование канала (TLS), целостность (HMAC)              |
| Учётные записи AD            | Аутентификационные данные                   | Хеширование паролей, MFA                                 |
| Реестры анализов лаборатории | Специальная категория ПДн                   | Шифрование, обезличивание, RBAC                          |

### Механизм тегирования данных

| Тег            | Уровень               | Описание                                   | Пример данных                            |
|----------------|-----------------------|--------------------------------------------|------------------------------------------|
| `PUBLIC`       | Общедоступные         | Данные, доступные без ограничений          | Адрес клиники, режим работы              |
| `INTERNAL`     | Внутренние            | Данные для сотрудников компании            | Внутренние регламенты, расписание врачей |
| `CONFIDENTIAL` | Конфиденциальные      | ПДн, финансовые данные                     | ФИО, телефон, платежи                    |
| `RESTRICTED`   | Ограниченного доступа | Специальные категории ПДн, врачебная тайна | Медкарты, диагнозы, анализы              |

Инструменты тегирования:
- Apache Atlas - каталог метаданных с возможностью тегирования
- OpenMetadata - open-source платформа для управления метаданными
- Средства DLP (InfoWatch, SearchInform) - автоматическое обнаружение и тегирование ПДн в потоках данных

| Управление согласиями      | CRM-модуль Consent Management                                    | Портал пациента, ресепшен         |
