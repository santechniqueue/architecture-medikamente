# Задание 3. Оценка Data Encryption at Rest and In Transit

## 1. Классификация данных

| Данные                               | В чём необходимость защиты                                                                                                                              | Инструменты защиты                                                                                   |
|--------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------|
| ФИО пациента                         | ПДн. Чувствительность: высокая. Идентификация личности, штрафы от регулятора, репутационные риски.                                                      | AES-256-GCM (at rest), TLS 1.3 (in transit), маскирование при отображении                            |
| Дата рождения                        | ПДн. Чувствительность: высокая. В связке с ФИО - однозначная идентификация пациента.                                                                    | AES-256-GCM (at rest), TLS 1.3 (in transit), обезличивание в аналитике (замена на возрастную группу) |
| Телефон, email                       | ПДн. Чувствительность: высокая. Каналы для фишинга и спама; утечка ведёт к мошенничеству и репутационным рискам.                                        | AES-256-GCM (at rest), TLS 1.3 (in transit), маскирование (+7***1234)                                |
| Адрес прописки                       | ПДн. Чувствительность: высокая. Риск физического преследования, кражи                                                                                   | AES-256-GCM (at rest), RBAC (доступ только для ресепшена)                                            |
| Паспортные данные                    | ПДн. Чувствительность: критическая. Мошенничество с документами, кредиты на чужое имя.                                                                  | AES-256-GCM (at rest), RBAC (только ресепшен при заключении договора), аудит каждого доступа         |
| СНИЛС, ИНН (сотрудников)             | ПДн. Чувствительность: критическая. Налоговое мошенничество, кража идентичности.                                                                        | AES-256-GCM (at rest), RBAC (доступ только для бухгалтерии)                                          |
| Медицинская карта (диагноз, анамнез) | Специальная категория ПДн + врачебная тайна. Чувствительность: критическая. Нарушение врачебной тайны - уголовная ответственность. Репутационный ущерб. | AES-256-GCM (at rest), TLS 1.3 + mTLS (in transit), ABAC (только лечащий врач), полный аудит доступа |
| Результаты анализов                  | Специальная категория ПДн + врачебная тайна. Чувствительность: критическая. Раскрытие диагнозов, дискриминация пациента.                                | AES-256-GCM (at rest), TLS 1.3 (in transit), обезличивание ID при передаче в лабораторию             |
| Хронические заболевания              | Специальная категория ПДн. Чувствительность: критическая. Дискриминация пациента.                                                                       | AES-256-GCM (at rest), ABAC (только лечащий врач), аудит                                             |
| Договоры с пациентами                | ПДн + коммерческая тайна. Чувствительность: высокая. Содержат паспортные данные, подписи, условия.                                                      | AES-256-GCM (at rest), RBAC (ресепшен + бухгалтерия)                                                 |
| Платёжные данные (чеки, суммы)       | Финансовые данные. Чувствительность: средняя. Финансовое мошенничество, нарушение коммерческой тайны.                                                   | TDE PostgreSQL (at rest), TLS 1.3 (in transit), токенизация номеров карт (PCI DSS)                   |
| Данные ККМ (фискальные)              | Финансовые данные. Чувствительность: средняя. Подделка фискальных данных, штрафы от регулятора.                                                         | TLS 1.3 (in transit), HMAC для целостности, защищённый канал ККМ-сервер                              |
| Зарплатные ведомости                 | ПДн + финансовые данные. Чувствительность: высокая. Утечка зарплат.                                                                                     | AES-256-GCM (at rest), RBAC (только бухгалтерия)                                                     |
| Кадровые данные                      | ПДн сотрудников. Чувствительность: высокая. Утечка персональных данных сотрудников.                                                                     | AES-256-GCM (at rest), RBAC (HR + бухгалтерия)                                                       |
| Учётные записи (логины/пароли)       | Аутентификационные данные. Чувствительность: критическая. Компрометация всей инфраструктуры, возможность доступа при компрометации.                     | bcrypt/Argon2id (хеширование), TLS 1.3, MFA, Vault для сервисных секретов                            |
| Реестры анализов лаборатории         | Специальная категория ПДн. Чувствительность: критическая. Связка ФИО-результат анализа = врачебная тайна.                                               | AES-256-GCM (at rest), TLS 1.3 (in transit), обезличивание в реестре                                 |
| Email-переписка (Exchange)           | Может содержать ПДн. Чувствительность: средняя. Утечка ПДн через email.                                                                                 | TLS 1.3 (in transit), S/MIME (at rest), DLP-контроль                                                 |
| Согласия на обработку ПДн            | Юридически значимые документы. Чувствительность: высокая. Без согласия обработка незаконна.                                                             | AES-256-GCM (at rest), неизменяемое хранение (append-only), аудит                                    |
| Журналы аудита доступа               | Операционные данные. Чувствительность: высокая. Фальсификация журналов для сокрытия утечки.                                                             | WORM-хранение (append-only), TLS при передаче, хеширование записей (SHA-256)                         |
| Расписание врачей, слоты записи      | Внутренние данные. Чувствительность: низкая. Минимальный риск, но может содержать конфиденциальную информацию.                                          | TLS 1.3 (in transit), стандартная защита БД                                                          |

## 2. Базовые инструменты защиты

### At Rest

| Инструмент                               | Назначение                                                  | Область применения                                  |
|------------------------------------------|-------------------------------------------------------------|-----------------------------------------------------|
| **AES-256-GCM** (field-level encryption) | Шифрование отдельных полей с конфиденциальными данными в БД | PostgreSQL - столбцы с ПДн (ФИО, паспорт, диагнозы) |
| **TDE (Transparent Data Encryption)**    | Шифрование всего хранилища данных прозрачно для приложений  | PostgreSQL (pgcrypto), ClickHouse (encrypted disks) |
| **BitLocker**                            | Шифрование дисков на уровне ОС                              | Физические серверы, рабочие станции                 |
| **HashiCorp Vault Transit**              | Управление ключами шифрования, ротация ключей               | Все сервисы, использующие шифрование                |
| **bcrypt**                               | Хеширование паролей                                         | IAM (Keycloak), Active Directory                    |

### In Transit

| Инструмент                | Назначение                               | Область применения                                           |
|---------------------------|------------------------------------------|--------------------------------------------------------------|
| **TLS 1.3**               | Шифрование всех сетевых соединений       | API Gateway, межсервисные вызовы, веб-порталы                |
| **mTLS (Mutual TLS)**     | Двусторонняя аутентификация сервисов     | Связь между микросервисами в Kubernetes (Istio service mesh) |
| **WireGuard / IPSec VPN** | Шифрование трафика между филиалами       | Межфилиальная сеть                                           |
| **S/MIME**                | Шифрование электронной почты             | Exchange Mail Server                                         |
| **HMAC-SHA256**           | Контроль целостности передаваемых данных | ККМ - 1С:Бухгалтерия, API лаборатории                        |

## 3. Автоматизированный контроль

| Средство контроля               | Описание                                     | Что контролирует                                                                           |
|---------------------------------|----------------------------------------------|--------------------------------------------------------------------------------------------|
| **SIEM**                        | Мониторинг безопасности в реальном времени   | Обнаружение аномалий доступа, попыток несанкционированного доступа, изменений конфигурации |
| **Prometheus + Grafana**        | Мониторинг метрик и алертинг                 | Производительность шифрования, латентность, количество обращений к тегированным данным     |
| **DLP**                         | Предотвращение утечек данных                 | Контроль email, сетевого трафика, USB-устройств, печати документов с ПДн                   |
| **Apache Atlas + Data Lineage** | Отслеживание происхождения и движения данных | Полный путь данных от источника до потребителя, автоматическое тегирование                 |
| **OPA (Open Policy Agent)**     | Автоматическая валидация политик доступа     | Проверка RBAC/ABAC-правил в CI/CD пайплайне перед релизом                                  |
| **Sonar Qube**                  | Сканирование уязвимостей                     | Проверка Docker-образов и зависимостей на CVE                                              |
| **Cert-manager**                | Автоматическое управление TLS-сертификатами  | Kubernetes - автообновление сертификатов, предотвращение истечения                         |
